# Inai backend

FastAPI backend for the Inai MVP. Requirements, design and tasks: `.kiro/specs/inai-mvp/`.

## Approved stack (M1)
Python 3.11, uv, FastAPI, Uvicorn, SQLAlchemy 2, Alembic, firebase-admin, pytest, PostgreSQL 16 (local-only for development). Authentication is tested with test doubles; the Firebase emulator is not used yet.

## Setup
`backend/uv.lock` is committed. Install the exact locked versions:
```bash
cd backend
uv sync --locked   # creates .venv from uv.lock; fails if uv.lock and pyproject.toml disagree
```

## Quality checks
```bash
uv run ruff format --check .
uv run ruff check .
uv run mypy
uv run pytest
```

## Status
- `uv.lock` is committed. It was generated by the manual `t04-lock-and-verify` workflow and reviewed before commit (all packages come from PyPI).
- The `backend-ci` workflow runs `uv sync --locked`, Ruff format and lint, mypy (strict) and pytest on pull requests and on pushes to `main` that touch `backend/**`. It passed on the commit that added the lock file (T0.4).
- PostgreSQL 16 connectivity (psycopg 3 against a `postgres:16` service container) was verified through the manual `t04-lock-and-verify` workflow. `backend-ci` does not start PostgreSQL.

## Updating dependencies
Dependency versions are pinned only by `uv.lock`. Do not edit it by hand.
1. Edit the dependency list in `pyproject.toml`.
2. Regenerate the lock with `uv lock` (from `backend/`).
   The manual `t04-lock-and-verify` workflow can also generate it and upload it as the `uv-lock` artifact. It never commits or pushes. As written it only runs from `m1/backend-foundation` (a guard in the workflow), and that branch is already merged. For a new dependency change, either use `uv lock` locally or change the guard in a separately reviewed workflow change.
3. Review the `uv.lock` diff. Check for unexpected packages, sources other than PyPI, and version changes you did not intend.
4. Run `uv sync --locked` and the quality checks above, then commit `pyproject.toml` and `uv.lock` together.

## Rules
- No production credentials, no real user data, no audio persistence.
- Identity comes only from verified Firebase tokens (test doubles in tests).
- The language catalog starts empty; no language is verified without evidence.
